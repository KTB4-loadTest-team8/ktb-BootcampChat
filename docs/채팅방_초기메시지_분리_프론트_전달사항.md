# 채팅방 초기 메시지 분리 - 프론트 전달사항

## 변경된 백엔드 동작

- `joinRoom` 성공 응답은 방 ID와 참가자 목록을 먼저 반환합니다.
- `joinRoomSuccess.messages`는 초기 응답 시 빈 배열입니다.
- `joinRoomSuccess.initialMessagesPending`가 `true`이면 초기 메시지를 별도 조회 중이라는 의미입니다.
- 초기 메시지 최대 30개는 조회 완료 후 기존 `previousMessagesLoaded` 이벤트로 같은 소켓에 전달됩니다.
- 초기 조회 실패 시 기존 `error` 이벤트와 동일한 `LOAD_ERROR` 코드가 전달될 수 있습니다.
- 기존 초기화 흐름은 `messages: []`를 정상적인 입장 응답으로 처리하므로, 추가적인 `fetchPreviousMessages` 요청 없이 `previousMessagesLoaded` 이벤트를 기다리게 됩니다.

## 프론트 확인 포인트

- 현재 프론트가 이미 `previousMessagesLoaded`를 구독하고 있으므로 이벤트 수신 후 메시지 목록에 병합되는지 확인합니다.
- `initialMessagesPending`가 `true`인 동안에도 채팅 입력창은 방 입장 성공 직후 렌더링되어야 합니다.
- 초기 메시지 이벤트 수신 전 빈 목록을 정상적인 로딩 상태로 처리하고, 이벤트 수신 후 `messages`와 `hasMore`를 갱신합니다.
- 재연결/빠른 방 전환 시 이전 방의 늦은 초기 메시지가 현재 방에 병합되지 않는지 확인합니다.

이번 백엔드 PR에서는 프론트 코드를 수정하지 않았습니다.
